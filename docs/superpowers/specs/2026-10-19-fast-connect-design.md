# 西农校园网助手启动架构改造设计（第二次审查）

状态：待用户确认；仅设计，未实现、未部署。取代《校园网助手-启动架构优化建议》的未定部分。

## 1. 用户确认的目标

登录 Windows 后，校园网络就绪即自动认证，正常情况下 5 秒内可以上网。无需打开应用、点击检测或额外运行脚本。无需登录前联网，因此采用当前用户权限的后台程序，不引入系统服务。

保持原有使用方式：无托盘；关窗口继续运行；再次打开显示现有实例；停止自动连接立即停止新检测和新认证，并在重启后保持暂停；关闭自启只影响未来启动；账号按当前 Windows 用户加密保存；现有校徽与布局继续使用。

5 秒是交付验收目标，不是目前已实现的结论，也不是学校服务器异常时的保证。用户希望减少反复修改，工程上通过一次完整改造、交付前集成测试与真机验证满足目标；不能仅以设计评审保证真实环境一定一次成功。

## 2. 证据与上一方案的修正

源码基线为公开仓库 v1.2.3，提交 34b77c8。本机目前运行 v1.2.2；两者启动架构相同。现有用户登录计划任务没有附加延迟。

本次检查记录到系统启动至应用进程启动约 21.8 秒。这段时间包含系统启动与登录，尚未取得用户登录和网络就绪的对齐记录，不能推算全部由程序造成，也不能把优化后的预期收益写成减少 22 秒。

现有后台依赖窗体构造、窗口消息线程和 500 毫秒定时器。网络变化只置 pending 标志，旧请求结束后才重新检测；引擎子进程总等待上限 45 秒。校验引擎、创建临时配置和启动外部进程也处于认证路径，但尚未测得其冷启动开销。

核对随 v1.2.3 发布的 BitSrunLoginGo v1.6.8 源码：引擎内部会再次读取登录状态；默认 HTTP 客户端可能使用代理环境变量。外层探测则明确不使用代理，因此两者网络路径可能不同。尚未证明本机受此影响，但新版本必须统一入口访问方式。

2026-10-19 在已联网状态下，无凭据查询学校状态接口三次，总耗时 146、36、65 毫秒（其中 DNS 41、4、7 毫秒）。这些数据只说明当前入口响应较快，不代表冷启动、离线认证或外网连通时间。

上一方案的不足及本次修正：

- 仅拆界面没有覆盖进程启动延迟：新增从登录、网卡就绪开始的端到端测量，启动延迟计入验收。
- 仅列 45 秒上限没有超时设计：新增每轮预算、超时后的状态确认和重试规则。
- 保留旧引擎没有解释重复查询：现阶段保留前置环境确认与引擎内部查询，优先保持兼容。测量到的状态查询成本较低，不为少一次请求重写协议；若完整认证基准仍无法达标，暂停交付并依据阶段计时定位，不宣称已完成。
- 没有具体升级切换流程：新增稳定安装目录、旧实例交接、任务路径核验和回滚。
- 认证成功不等于可上网：新增独立外网验证，单独记录两个结果。

## 3. 推荐架构及边界

采用一个后台进程、独立连接工作循环、按需创建窗体的结构。避免为本次需求引入 Windows 服务、多个常驻进程或新的凭据传输通道。

### 启动宿主

进程进入后先记录启动标记，校验运行环境、获取单实例锁、加载凭据和暂停状态、启动连接核心。自启时不构造 MainWindow，不读取校徽、不绘制控件。界面样式与资源初始化延后到用户主动打开时。

宿主可用无主窗体的 ApplicationContext 保持应用生命周期，但连接核心不能依赖 GUI 消息泵。显示请求使用已存在的同用户事件机制；先创建显示事件再接受重复启动，补上初始化期间重复双击的竞态处理。自动启动的重复实例不唤起窗口。停止后宿主仍可接受界面打开请求，便于恢复启动。

### 连接核心

独立 ConnectionController 持有账号快照、暂停状态、网络代次、取消令牌、单调时钟、下一次截止时间和当前尝试任务。界面只发送命令、读取不可变状态快照。核心向界面发布状态时不得等待界面回调完成。

同一时刻只允许一个认证任务。Start、Stop、CheckNow、NetworkChanged、Resume 由串行命令处理协调；所有异步结果附带代次，过期结果不能把暂停或新网络状态覆盖为在线。Stop 先持久化暂停并撤销重试，然后取消当前工作；已经发到学校的请求无法撤回，停止不等于注销网络。

重试等待使用可唤醒等待机制，网络事件和人工命令直接唤醒，不等待下一次 GUI Tick。网络观察订阅先于初次网络快照，避免启动期间漏掉事件。

### 网络就绪与事件处理

网卡链路、有效地址与到学校入口的候选路由用于判断是否值得探测；不得以 Windows 已显示“可访问 Internet”作为认证前提，因为待认证网络本就可能没有外网。

网卡信息只用于触发，学校入口的有效 HTTPS 响应用于确认认证环境。不能把任意私网地址或相同 Wi-Fi 名称当作学校身份。保持固定域名、证书验证、禁止自动重定向及现有协议响应校验。

事件合并窗口 150 毫秒；只有相关接口、地址或路由发生有效变化才更新网络代次。无关虚拟网卡事件不重启正在进行的认证。网络变化取消旧的只读探测；认证提交阶段不被每个通知打断，保留一个后续检查标志。确实失去路由时取消子进程，确认退出后再开始新轮；恢复时先检查状态，避免上一请求已被服务端执行后又重复登录。

### 请求与认证预算

第一次检测立即开始。启动或网络恢复后的前 30 秒是快速恢复窗口：失败后的只读检查间隔为 0.5、1、2 秒，之后保持 2 秒；离线持续更久按 5、10、30、60 秒退避。相同网络的重复通知不无限重置窗口。已有认证提交后，两次提交之间至少 2 秒；明确密码错误、设备上限或认证拒绝暂停，不因网络事件解除。

学校只读探测采用真正的整次截止时间：快速窗口 1.5 秒，普通检查 3 秒，覆盖 DNS、连接、TLS、读取。DNS 未能取消时不得积累无限并发解析任务；同一网络复用未完成解析，限制数量，并丢弃过时代次结果。

引擎仍使用固定校验版本，单个 HTTP 请求配置超时 2 秒、整次子进程预算 8 秒；只重试网络类失败，恢复阶段允许单次 4 秒请求／15 秒整次预算的慢路径，随后按退避策略继续。8 秒与 15 秒是故障控制上限，不是正常路径等待，也不等于 5 秒验收通过。所有取消、输出读取和进程回收都必须有界；清理失败不得阻塞下一轮，也不得直接同时启动第二个认证进程。

仅在子进程环境中移除代理相关环境变量，保持系统和其他程序设置不变；不绕过证书校验。临时配置继续放在限制权限的数据目录并在所有退出路径清理。引擎校验采用现有哈希要求；先测量耗时，本次不通过取消校验换取速度。

若引擎超时或输出含义不明，先查询学校状态确认是否已经成功。未识别输出归为未知故障并有限重试、记录错误分类，不能伪装成明确密码错误；已确认的账号问题仍暂停，避免高频错误登录。

正常在线保持 60 秒检查一次。关闭窗口、界面阻塞、异常提醒弹窗均不能暂停连接核心。

### 自启和安装迁移

首次设置完成后，将可执行文件、资源和引擎部署到固定的当前用户应用目录，例如 `%LOCALAPPDATA%\Programs\NWAFU-CampusConnect`；数据仍保存在原数据目录，避免版本号目录与下载解压位置影响下次启动。分享包内不包含个人凭据或日志。

自启开关统一维护用户登录计划任务、Run 回退和启用标志；计划任务直接执行稳定路径主程序的 `--autostart`，去掉 EarlyStart 的额外进程跳转。程序自启入口读取启用标志与暂停状态；关闭自启后，残留任务也不得恢复自动启动。注册完成读回任务和 Run 路径验证，不把仅有某个键值当作成功。快速任务注册失败时明确显示“普通自启”，不宣称已启用快速模式。

迁移先备份本项目的原启动配置及旧程序，检查新文件完整性，然后进行受控实例切换。旧版不具备退出命令时，升级流程只处理已核实路径和文件身份的本项目旧进程，绝不按模糊进程名批量结束。切换期间不执行校园网注销操作。若认证子进程尚在运行，先等待有界结束或取消后确认退出，防止双重认证。

新版启动成功并报告版本后，再移除本项目已知旧入口。失败恢复原路径和任务。保留既有 DPAPI 数据与暂停状态，不要求重新输入密码，不擅自开启原本关闭的自启。Windows 本身禁用的启动项或权限不足，应作为可见诊断，不能静默报成功。

## 4. 可测量的五秒验收

定义时间点：

- L：本次用户交互登录时间。
- N：校园接口有效地址和候选路由可用的最早可观测时间。
- T0 = max(L, N)。网络在登录前已可用时从登录开始计时；网络登录后才就绪时从网络就绪开始计时。
- P：进程入口，Q：首次学校探测，A：认证请求开始，C：学校在线状态确认，I：外网连通验证成功。

正常目标为 `I - T0 ≤ 5 秒`，同时报告 `P - T0`、`Q - P`、`C - Q`、`I - C`。不得将 T0 改成程序启动或首次收到学校成功响应，掩盖启动延迟。

日志用单调时钟测量进程内部阶段；跨进程和系统事件使用同次启动的时间锚对齐，并标记精度。若无法取得可靠 N 或 L，标记测量不足，不能声称端到端五秒达标。验收前应启用适当的系统网络事件记录；若事件只表示网络识别完成、不代表最早地址和路由就绪，必须注明偏差，并补充测试观测。

参考分配预算（目标，不是各阶段强制取消点）：启动与调度 0.8 秒，初次探测 0.5 秒，引擎启动与认证 2.5 秒，在线确认及外网验证 1.2 秒。实际记录各阶段，不能仅比较总数。

“正常”样本事前限定为：已保存有效凭据、自启启用且未暂停、正确校园链路、没有学校明确认证拒绝。每个样本都保留结果，不能把所有慢样本事后都归为网络异常。DNS/TLS 故障、服务器超时等须以阶段证据标明；无法归因的超过 5 秒样本视为未达标。

外网验证采用两个固定 HTTPS 端点并行择一成功：`https://www.baidu.com/robots.txt` 和 `https://www.qq.com/robots.txt`。禁止重定向，要求证书有效、HTTP 200，最多读取 4096 字符并确认包含标准 User-agent 字段；整体预算 1 秒，成功后取消另一请求。仅在启动／网络恢复后的在线确认和人工检测时运行，不跟随每次正常保活重复访问。端点可用性变化应独立诊断，不能把一个站点异常当作全网断开。

本次实际测得这两个端点分别为 266、285 毫秒，均符合内容检查。另两个候选中，一个请求失败，一个耗时 2925 毫秒，因此未采用；这说明外网检测地址选择本身也会影响用户看到的“联网速度”。上述数值是当前环境样本，不能作为重启后的性能保证。

验证用于区分“学校已认证”和“已验证外网连通”，不作为提交账号的前提，不向探测站点发送账号或认证令牌。探测失败时不反复重新登录已经在线的校园账号；显示“已认证，外网检测未通过”，后台以 1、2、5 秒间隔补测，恢复后停止补测。五秒内未取得外网证据的样本不能标记为五秒验收成功，同时保留学校认证完成时间。

## 5. 日志与测试门槛

日志记录版本、运行 ID、启动来源、网络代次、阶段耗时、状态和错误类型；不记录账号、密码、IP、令牌、完整请求 URL、原始认证响应。使用追加和轮转，写入不阻塞认证。写入失败保留内存诊断并在界面显示，不能再次出现旧日志被误认作本次记录。旧数据目录和新宿主必须在实际登录用户环境核验。

交付前依次验证：

1. 核心测试：无窗体无 GUI 消息泵仍能认证；界面线程阻塞期间后台继续；首次调度无固定延迟；同一网络事件合并且永不并发认证。
2. 故障测试：DNS 不返回、TLS 失败、读取不结束、子进程挂起、输出格式变化、日志写入失败、进程取消、地址切换、Stop 与旧结果竞争、认证提交后响应丢失。每种故障都有有界恢复或明确暂停状态。
3. 使用行为：关闭／重开窗口、暂停跨重启、关闭自启不停止当前运行、清除账号、错误密码暂停、用户临时不保存密码时关闭自启。
4. 安装升级：旧版正在运行、重复点击安装、任务注册失败、安装路径有空格中文、新文件缺失、旧入口并存、安装中断和回滚。核对实际运行版本及任务目标。
5. 基准对比：在相同模拟延迟下对比旧版与新版；模拟测试只证明调度性质，不替代校园认证实测。
6. 真机验收：至少 3 次系统“重启”及 2 次网络恢复样本。全程不打开软件或手动检测；分别记录是否原本已在线。至少 1 次确实需要重新认证的有效样本，不能用所有已在线样本证明认证速度。主动断网或注销需安排在用户认可的测试时段，不能擅自打断当前会话。

只有功能测试通过、稳定路径迁移成功、真机有效样本符合五秒目标，才对用户宣称本机验收通过并制作正式推荐包。测试包可用于重启采样，但明确标识待验收，不覆盖发布结论。若真实延迟来自进程启动前，先定位任务触发与系统调度，不继续盲目缩短认证重试；若来自引擎或网络，使用已记录阶段决定下一步。学校升级或其他电脑的表现不由本机少量样本保证。

## 6. 本次确认范围

确认本设计即确认：用户级后台核心、保留认证算法、快速自启自动配置、稳定路径升级，以及上述五秒测量和验收规则。登录前联网、系统服务、协议重写、UI 改版不包含在本次范围。

设计确认后编写具体实施计划。当前尚未修改应用代码、停止现有进程、迁移安装或提交任何认证请求。
